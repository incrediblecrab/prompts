# D3

Use for custom data visualization with D3 in JavaScript or TypeScript. Follow the installed APIs and existing rendering architecture. Import the functions or modules needed for the task; do not copy legacy event or scale APIs without checking compatibility.

## Own the rendering boundary

Use D3 for scales, geometry, layouts, and data transforms without DOM mutation when the framework owns rendering. If D3 manages elements, give it a dedicated subtree and scope selections to that root. Do not let D3, a framework, or Plotly compete over the same nodes.

Pure calculations may run on the server. DOM selection, measurement, and interaction need a suitable DOM environment; browser-only code must not run during server rendering.

## Join and update

Use stable, unique data keys and an appropriate `selection.data(...).join(...)` when D3 owns changing marks. Handle entering, updating, and exiting elements rather than appending duplicates or clearing the whole chart on each update.

Validate and parse data before scaling. Handle empty inputs, missing values, non-finite numbers, and degenerate domains explicitly. Represent missing observations as gaps where appropriate, not invented zeros. Keep units, time zones, ordering, and baseline choices consistent with the comparison.

Recompute ranges and layout when the container changes size. Preserve intended focus, selection, and zoom state across compatible updates.

## Lifecycle and usability

Initialize once per owned instance. On teardown, remove namespaced listeners, disconnect observers, stop timers and force simulations, and interrupt owned transitions, including affected descendants and named transitions. Prevent stale callbacks from updating removed nodes.

Choose SVG, Canvas, or another existing renderer based on measured needs and the required interactions, not a universal point-count threshold. Respect reduced motion and provide keyboard/touch alternatives to pointer-only interactions.

Label the evidence clearly, use accessible contrast and non-color cues, and provide a text or data alternative. Surface invalid input or rendering errors explicitly.

Check data replacement, reordering, insertion/removal, resize, and repeated mount/unmount. Verify that updates do not accumulate nodes, handlers, or background work.

References: [getting started](https://d3js.org/getting-started), [data joins](https://d3js.org/d3-selection/joining), [transition lifecycle](https://d3js.org/d3-transition/control-flow).
